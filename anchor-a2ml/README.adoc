== What Is ANCHOR?

ANCHOR is an *intervention format* for the Hyperpolymath estate. When a
project or AI agent drifts from its intended path, an ANCHOR file provides
authoritative, time-limited directives for realignment.

ANCHOR is the *is/ought join*: it reconciles what a repository's DEED
declares (the projection) with what reality shows (the fiber), and issues
directives to close the gap.

[NOTE]
====
*Echo typing:* In the estate's type-theoretic framework, a DEED is a
projection of a repo's actual state. The fiber over a declaration is
everything the projection lost. ANCHOR is the point where the two are
forced back together. See
link:../deed/spec/DEED-GRAMMAR-SPEC.adoc#echo[DEED spec §7.2.3].
====

== What ANCHOR Is NOT

* *Not a DEED.* DEED files are immutable epistemic records. ANCHOR files
  are ephemeral intervention directives with expiration dates.
* *Not a K9 file.* K9 Coordination governs ongoing agent behavior. ANCHOR
  is a point-in-time correction that may instruct agents to update K9.
* *Not an A2ML file.* The A2ML format family is superseded. ANCHOR now
  uses S-expression syntax consistent with DEED.
* *Not a Scheme program.* Despite the S-expression syntax, ANCHOR files
  are data, not code. They are parsed, not evaluated.

== When to Use ANCHOR

| Situation | ANCHOR Type |
|-----------|-------------|
| *Scope drift* — project expanded beyond charter | `scope-arrest` |
| *Direction change* — strategic pivot | `direction-change` |
| *Stock-taking* — periodic alignment review | `stock-taking` |
| *Emergency halt* — critical issue | `emergency-halt` |
| *Course correction* — minor trajectory fix | `course-correction` |

== File Identity

[cols="1,2"]
|===
| Extension | `.anchor`

| Location | Repository root or `.machine_readable/`

| Syntax | S-expression (DEED lexical layer)

| Magic | None (identified by `(anchor ...)` head and extension)

| Encoding | UTF-8, no BOM

| Lifecycle | Ephemeral — created for an intervention, archived or
  deleted after verification
|===

== Relationship to DEED and K9

[cols="1,2"]
|===
| Format | Relationship

| *DEED* (`*_chora.deed`)
| ANCHOR targets a specific repo chora via `:target-chora <uuid>`. The
  chora provides the declared state (the "ought"); ANCHOR addresses the
  drift from it (the "is"). ANCHOR never modifies DEED files.

| *K9 Coordination* (`coordination.k9`)
| ANCHOR directives may instruct agents to update `coordination.k9`
  (e.g., add invariants, update coordination state). ANCHOR itself is
  not a K9 section.

| *Estate chora* (`estate_chora.deed`)
| ANCHOR does not reference the estate chora directly. It targets a
  specific repo.
|===

*The intervention flow:*

----
1. Drift detected (by cadastre, agent, or human)
2. Superintendent creates ANCHOR.anchor
   - :target-chora references the repo's DEED
   - directives specify corrections
3. Agent reads ANCHOR at session start
4. Agent executes directives (may update coordination.k9)
5. Verification criteria checked
6. ANCHOR archived or deleted after success/expiration
----

== Quick Start

=== 1. Create the ANCHOR file

Name it `ANCHOR.anchor` or `ANCHOR-<purpose>-<date>.anchor`.

=== 2. Write the intervention

[source,scheme]
----
;; SPDX-FileCopyrightText: © 2026 Jonathan D.A. Jewell
;; SPDX-License-Identifier: MPL-2.0
(anchor
  :schema-version "1.0.0"
  :target-chora #u5"casket-ssg/v1.0.0"
  :issued "2026-04-09"
  :expires "2026-05-09"

  (authority
    :superintendent "Jonathan D.A. Jewell"
    :role "Project Owner"
    :level full)

  (purpose
    :type scope-arrest
    :summary "Halt scope expansion and stabilize architecture"
    :symptoms ("Feature creep in last 3 sprints"
               "Test coverage declining")
    :desired-outcome ("Return to core value proposition"
                      "Stabilize before new features"))

  (directives
    (directive
      :action "halt-new-features"
      :priority critical
      :phase immediate
      :description "No new feature work until backlog cleared")
    (directive
      :action "review-architecture"
      :priority high
      :phase this-week
      :description "Review and update architecture decisions"))

  (target-review
    (review :target coordination-k9 :required #t
            :focus ("invariants" "protected-paths"))
    (review :target repo-chora :required #f))

  (verification
    (criterion :name scope-contained
               :measure "No new features in backlog")
    (criterion :name state-accurate
               :measure "coordination.k9 matches reality")
    :method checklist
    :reviewer "superintendent"
    :deadline "2026-04-16"))
----

=== 3. Drop into repository

Place in the repository root.

=== 4. Instruct agents

Tell agents: "Read `ANCHOR.anchor` before proceeding with any work."

== Execution Protocol

=== Discovery

Agents SHOULD check for `*.anchor` files:

* At session start
* When directed to the repository root
* After receiving "anchor" or "realign" commands

=== Processing

When an ANCHOR file is found:

. Parse and validate against `anchor.abnf`.
. Verify `:target-chora` matches the repository's DEED.
. Check `:expires` — if expired, treat as advisory only.
. Check `:supersedes` — if set, verify the referenced anchor is archived.
. Acknowledge the purpose to the user.
. Execute directives in priority order (`critical` → `high` → `medium`
  → `normal` → `low`).
. Perform target review as specified.
. Report verification status.

=== Supersession

A new ANCHOR file supersedes:

* Any prior ANCHOR with a matching `:supersedes` chain
* Accumulated context that conflicts with directives
* Cached assumptions about project state

=== Expiration

Expired ANCHORs SHOULD be treated as advisory only. Agents SHOULD NOT
execute directives from expired ANCHORs without explicit user approval.

== Security Considerations

* *Authority verification:* Implementations SHOULD verify the
  `:superintendent` against known project owners.
* *Expiration:* ANCHOR files SHOULD have `:expires` dates. Expired
  ANCHORs are advisory only.
* *Audit trail:* All ANCHOR processing MUST be logged.
* *No self-execution:* ANCHOR files are data, not code. They instruct
  agents but do not execute themselves.

== Migration from A2ML

The previous `ANCHOR.a2ml` (TOML-like) and `ANCHOR.scm` (Scheme module)
formats are *superseded*. Migration steps:

. Replace `[section]` + `key = value` syntax with S-expression syntax.
. Replace `(define ...)` Scheme forms with `(anchor ...)` data forms.
. Change extension from `.a2ml` or `.scm` to `.anchor`.
. Add `:target-chora` UUID5 referencing the repo's DEED.
. Add `:schema-version` as the first field.
. Remove any executable Scheme code (ANCHOR is data, not code).
