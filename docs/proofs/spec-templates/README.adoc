== Proof Specifications — LLM Handoff Directory

=== Purpose

This directory contains *executable proof specifications* for all 292
repos in the hyperpolymath estate. Each spec is designed so that any
coding LLM with proof-checker tooling (Gemini + MCPs to
`+coqc+`/`+lean+`/`+agda+`/`+idris2+`, or similar) can pick up one file
and produce verified proofs independently.

=== How to Execute a Spec (for LLMs)

You have been given ONE `+.md+` spec file from this directory. Follow it
exactly:

[arabic]
. *Read the entire spec file* before starting. Note the target repo,
prover(s), and total theorem count.
. *Navigate to the target repo* at the path given in the spec.
. *Create the proof files* at the exact paths specified in the spec.
. *Write each theorem* matching the signature/statement given.
. *NEVER use banned patterns*: `+believe_me+`, `+assert_total+`,
`+postulate+`, `+sorry+`, `+Admitted+`, `+unsafeCoerce+`, `+Obj.magic+`.
Each spec repeats this reminder.
. *Run the verification command* given at the end of the spec. All
proofs MUST check successfully.
. *Update the repo’s `+PROOF-STATUS.md+`* with completed rows.
. *Commit* with message:
`+proof: complete <spec-name> proofs (N/M theorems)+`

=== Spec Format

Every spec contains:

* *Header*: repo name, tier, proof count, prover(s)
* *Context*: what the repo does, source file tree
* *Existing proofs*: what is already verified (do not redo)
* *Theorems*: numbered list with:
** Theorem ID (e.g., `+E1+`, `+V3+`)
** Target file (where proof lives)
** Source file + line range (what code is being verified)
** Prover and file extension
** Statement (formal or semi-formal)
** Expected signature (typed skeleton)
** Hints and obligations
* *Verification commands*: shell commands to check all proofs
* *Banned patterns*: reminder
* *Handoff checklist*: final verification steps

=== Parallelism Strategy

Multiple LLMs can work on different spec files simultaneously without
conflict, because: - Each spec targets one repo - Each spec lists files
that do not overlap with other specs - All specs follow the same
protocol (banned patterns, verification commands)

Suggested allocation: - Assign T1 specs to the strongest LLMs (critical
safety proofs) - Assign T2 specs to mid-tier LLMs - Assign T3 specs to
any LLM with proof-checker MCP access - T4 specs can be auto-generated
from the template

=== Dependencies Between Specs

Some proofs depend on others. Each spec lists upstream dependencies.
Execute in this order:

[arabic]
. *`+proven+` repo* first (foundational Idris2 library)
. *`+rsr-template-repo+` ABI proofs* second (baseline for all repos)
. *T1 repos* third (each self-contained)
. *T2/T3 repos* any time after their ABI dependencies

=== Questions / Clarifications

If a spec is unclear or a theorem cannot be proven as stated: 1.
Document the blocker in the spec file (add a `+Blockers+` section) 2. Do
NOT invent or weaken the theorem 3. Mark the status as
`+Blocked — needs human review+` 4. Move on to the next theorem
