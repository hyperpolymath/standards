=== Rust Secure Coding Practices

==== Rust Security Model

Rust’s security model is based on: 1. *Memory safety*: Ownership,
borrowing, lifetimes 2. *Type safety*: Strong static typing 3.
*Zero-cost abstractions*: Safety without performance overhead 4.
*Explicit unsafe*: Clear boundaries for unsafe code

==== Common Rust Vulnerabilities

[cols=",,",options="header",]
|===
|Vulnerability |Prevention |Detection Tool
|Use-after-free |Ownership system |Clippy, Miri
|Buffer overflows |Bounds checking |Clippy, Miri
|Data races |Send/Sync traits |Clippy
|Integer overflows |Checked arithmetic |Clippy
|Unsafe code issues |Minimize unsafe blocks |cargo-geiger
|===

==== Rust Toolchain Setup

[source,bash]
----
# Install Rust toolchain with security tools
rustup toolchain install stable
rustup component add rustfmt clippy rust-analysis

# Install security tools
cargo install cargo-audit cargo-geiger cargo-license cargo-outdated
----

==== Rust Security Tools Guide

===== 1. Clippy (Linting)

*Purpose:* Catch common mistakes and suspicious patterns

*Key lints for security:* - `+clippy::integer_arithmetic+` - Integer
overflow checks - `+clippy::unwrap_used+` - Panic prevention -
`+clippy::indexing_slicing+` - Bounds checking -
`+clippy::float_arithmetic+` - Floating point issues

*Usage:*

[source,bash]
----
# Run clippy with security-focused lints
cargo clippy --all-targets --all-features -- -D warnings -W clippy::pedantic

# Fix specific issues
cargo clippy --fix --allow-dirty --allow-staged
----

===== 2. Rustfmt (Formatting)

*Purpose:* Consistent code style reduces review burden

*Security benefits:* - Consistent error handling patterns - Clear unsafe
code boundaries - Readable security-critical code

*Usage:*

[source,bash]
----
# Check formatting
cargo fmt --all -- --check

# Apply formatting
cargo fmt --all
----

===== 3. Cargo Audit (Security Auditing)

*Purpose:* Dependency vulnerability scanning

*Usage:*

[source,bash]
----
# Install
cargo install cargo-audit

# Run audit
cargo audit

# Update advisory database
cargo audit fetch

# Check for outdated dependencies
cargo outdated
----

*Interpreting results:* - *High severity*: Immediate action required -
*Medium severity*: Schedule fix in next release - *Low severity*:
Document and monitor

===== 4. Cargo Geiger (Unsafe Code Analysis)

*Purpose:* Detect and quantify unsafe code usage

*Usage:*

[source,bash]
----
cargo install cargo-geiger
cargo geiger
----

*Safe code guidelines:* - Minimize `+unsafe+` blocks - Isolate unsafe
code in separate modules - Document safety invariants - Use safe
abstractions

==== Rust Secure Coding Checklist

[source,markdown]
----
- [ ] Use `?` operator instead of `unwrap()`/`expect()`
- [ ] Validate all external inputs
- [ ] Use checked arithmetic (`checked_add`, `saturating_sub`, etc.)
- [ ] Implement proper error handling
- [ ] Minimize `unsafe` code blocks
- [ ] Use `#[deny(unsafe_code)]` where possible
- [ ] Document safety invariants for unsafe code
- [ ] Run `cargo clippy -- -D warnings` before commit
- [ ] Run `cargo audit` weekly
- [ ] Keep dependencies updated
----

=== Julia Secure Coding Practices

==== Julia Security Model

Julia’s security focuses on: 1. *Type stability*: Predictable
performance and behavior 2. *Memory safety*: Garbage collection and
bounds checking 3. *Package isolation*: Environment system 4. *Code
evaluation safety*: Sandboxing capabilities

==== Common Julia Vulnerabilities

[cols=",,",options="header",]
|===
|Vulnerability |Prevention |Detection Tool
|Type instability |Type annotations |JET.jl
|Injection attacks |Input validation |Aqua.jl
|Dependency issues |Package pinning |Aqua.jl
|Code evaluation risks |Avoid `+eval+`, `+include+` |Static analysis
|Race conditions |Proper synchronization |ThreadSanitizer
|===

==== Julia Toolchain Setup

[source,julia]
----
# Set up Julia environment
using Pkg
Pkg.add([
    "JuliaFormatter",
    "JET", 
    "Aqua",
    "BenchmarkTools",
    "Coverage"
])
----

==== Julia Security Tools Guide

===== 1. JuliaFormatter.jl

*Purpose:* Consistent code style

*Usage:*

[source,julia]
----
using JuliaFormatter
# Check formatting
format("."; overwrite=false)
# Apply formatting  
format(".")
----

*CI Integration:*

[source,yaml]
----
- name: Julia format check
  run: julia -e 'using JuliaFormatter; format("."; overwrite=false)'
----

===== 2. JET.jl (Static Analysis)

*Purpose:* Type inference and error detection

*Key checks:* - Type stability analysis - Method ambiguity detection -
Unreachable code detection - Potential runtime errors

*Usage:*

[source,julia]
----
using JET
# Basic analysis
report_package(".")
# Comprehensive testing
JET.test_package(path=".")
----

*Interpreting JET reports:* - *Type instability*: Add type annotations -
*Method ambiguities*: Resolve with more specific methods - *Unreachable
code*: Remove dead code - *Potential errors*: Add validation checks

===== 3. Aqua.jl (Package Quality)

*Purpose:* Package health and security checking

*Key tests:* - *Ambiguity detection*: Method conflicts - *Dependency
compatibility*: Version conflicts - *Project extras*: Proper package
structure - *Stale dependencies*: Outdated packages

*Usage:*

[source,julia]
----
using Aqua
# Run all tests
Aqua.test_all(MyPackage)
# Test specific aspects
Aqua.test_ambiguities(MyPackage)
Aqua.test_deps_compat(MyPackage)
----

*CI Integration:*

[source,yaml]
----
- name: Julia package audit
  run: julia -e 'using Aqua; Aqua.test_all(deps=true)'
----

==== Julia Secure Coding Checklist

[source,markdown]
----
- [ ] Use type annotations for public functions
- [ ] Validate all external inputs
- [ ] Avoid `eval` and `include` with untrusted input
- [ ] Use proper error handling (`try-catch`)
- [ ] Pin dependency versions in `Project.toml`
- [ ] Run `JuliaFormatter.format(".")` before commit
- [ ] Run `JET.test_package(".")` in CI
- [ ] Run `Aqua.test_all()` weekly
- [ ] Document all exported functions
- [ ] Maintain >80% test coverage
----

=== CI/CD Pipeline Training

==== Understanding Our CI/CD Setup

===== Rust Project Pipeline

*Stages:* 1. *Check*: Format and lint verification 2. *Build*:
Compilation and artifact creation 3. *Test*: Unit and integration tests
4. *Security*: Vulnerability scanning 5. *Deploy*: Documentation and
release

*Key Files:* - `+.github/workflows/rust-ci.yml+` (GitHub Actions) -
`+.gitlab-ci.yml+` (GitLab CI)

===== Julia Project Pipeline

*Current Setup:* - Basic testing via `+Pkg.test()+` - Quality checks in
`+quality.yml+`

*Recommended Enhancement:*

[source,yaml]
----
# Add to .github/workflows/quality.yml
jobs:
  julia-security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: julia-actions/setup-julia@v2
      - name: Install security tools
        run: julia -e 'using Pkg; Pkg.add(["JuliaFormatter", "JET", "Aqua"])'
      - name: Format check
        run: julia -e 'using JuliaFormatter; format("."; overwrite=false)'
      - name: Static analysis
        run: julia -e 'using JET; JET.test_package(".")'
      - name: Package audit
        run: julia -e 'using Aqua; Aqua.test_all()'
----

==== CI/CD Best Practices

[arabic]
. *Security Stage Isolation*: Run security checks in dedicated stage
. *Allow Failure*: Use `+continue-on-error+` for non-blocking checks
. *Artifact Preservation*: Save security reports as artifacts
. *Regular Scheduling*: Run audits on schedule, not just on push
. *Dependency Updates*: Automate dependency update PRs

==== Pipeline Maintenance

*Monthly Tasks:* - Review and update dependency versions - Check for new
tool versions - Review security findings - Update advisory databases

*Quarterly Tasks:* - Review pipeline performance - Update base
images/containers - Audit pipeline permissions - Review tool
effectiveness

=== Static Analysis Deep Dive

==== Understanding Static Analysis

*Types of Analysis:* 1. *Lexical analysis*: Token patterns 2. *Syntax
analysis*: AST patterns +
3. *Semantic analysis*: Type and flow analysis 4. *Data-flow analysis*:
Variable tracking 5. *Control-flow analysis*: Execution paths

==== Common False Positives

*Rust Clippy:* - `+clippy::needless_pass_by_value+` - Sometimes
intentional - `+clippy::module_name_repetitions+` - Can be idiomatic -
`+clippy::too_many_arguments+` - Context-dependent

*Julia JET:* - Type instability in generic code - False positives in
macro-generated code - Overly conservative ambiguity detection

==== Handling Analysis Results

*Triage Process:* 1. *Reproduce*: Verify the issue exists 2. *Assess*:
Determine severity and impact 3. *Prioritize*: High/medium/low priority
4. *Fix*: Implement correction 5. *Verify*: Confirm fix resolves issue
6. *Document*: Add suppression if appropriate

*Suppression Methods:*

*Rust (Clippy):*

[source,rust]
----
#[allow(clippy::lint_name)]
fn my_function() {}
----

*Julia (JET):*

[source,julia]
----
# JET.jl doesn't have suppression, document in code comments
# JET-ISSUE: Type instability intentional for performance
function my_func()
    # ...
end
----

*Objective:* Run and interpret security tools on a Rust project

*Steps:* 1. Clone the asdf-acceleration-middleware repository 2. Run
