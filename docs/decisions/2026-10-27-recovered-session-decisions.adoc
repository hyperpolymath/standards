== K9 / deed / contractiles overhaul (rulings Q1–Q16, 2026-10-19/20)

Source: the "K9-deed and standards system overhaul" session. The plan landed as
`docs/ULTRAPLAN-DEED-K9-CONTRACTILES-2026-10-19.adoc` (#1313, merged 2026-10-20) and the Q16
follow-up (#1322, merged 2026-10-20). The ultraplan, not this record, is the authority on
wording. Nothing beyond the planning documents had been implemented.

* *Q1, the verbs.* The Intentfile is the north star (normative); the Mustfile holds the
  invariants; the Trustfile holds security, privacy and safety; the Adjustfile holds
  accessibility; the Bustfile holds how to fix breakage and the likely failure pathways; the
  Dustfile holds exnovation, stripping down and retiring. ADJUST is also a descriptile.
* *Q3, the must runner (Nickel).* It checks the Mustfile against the descriptiles (META,
  ECOSYSTEM, STATE, PLAYBOOK, AGENTIC, NEUROSYM). Everything stops until the contract is
  renegotiated or the violation is fixed. A `trust` violation also stops the run.
* *Q4.* The deed attests each party's state (Adjustfile contract against ADJUST reality). There
  is one ABNF per format, so three.
* *Q5, versioning.* One rule for the deed, K9 components and `coordination.k9`: three segments,
  MAJOR.MINOR.PATCH. A wrong major is refused, a higher minor is accepted with a warning, and
  a two-segment version is refused. Both validators change.
* *Q6.* Assurance-envelope fields (scope, assumptions, boundaries, evidence label) go on each
  contractile clause in `_base.ncl`; Panoply is the pilot.
* *Q7.* Panoply-class files renamed from the retired format to `.deed` are translated where a
  mapping spec exists and deleted where none does.
* *Q8.* `hyperpolymath/contractiles` holds only the runner; the spec lives in this repository
  under `1-formats/contractiles/`.
* *Q9 (selector: "Split by tier").* Policy is separate from the Hunt-tier signed executor.
  Probes stay refused and checks report "blocked", never "passed", until CI has a real
  signature verifier. The session called for `rsr-template-repo#247` to be revised to match;
  #247 merged on 2026-10-20, so any revision is now a follow-up on main (not yet checked).
* *Q10–Q15 (selector, recommended arms).* The K9 envelope grammar is an ABNF plus Nickel and
  becomes the test oracle for `k9-validate.sh`. `(anchor …)` is a deed clause. There is one
  descriptile clause per verb. The Verbfile is a concept: two files per verb and no separate
  Verbfile. `(contractiles …)` is a deed clause and `:contractiles_required` is derived from
  it. The AI manifest is a pointer-only front door, with its fields moved into the repo deed.
* *Q16.* The UX standards' `<app>-dustfile.sh` repair-script specification belongs to the
  Bustfile (self-healing, self-diagnosing fix scripts, partial fixes that acknowledge a
  failure). The Dustfile keeps exnovation ("from dust to dust"). The specification and its
  template are to be renamed to Bustfile names.

Corrections made during the work, so they are not repeated: the manifest count was 95, not 48;
the `hypatia-ref` default is a pinned SHA, so a rollout must advance the default and repin every
enrolled caller with `scripts/propagate-workflow-pins.sh`; the template has no `.contractile`
files and this repository has four. The `contractile` runner exposes `adjust` but reads the
descriptile; the verb it lacks is `bust`.

== actions.lock and the repository move

* Actions does not follow the 301 from `hyperpolymath/standards` to `metadatastician/standards`
  for `uses:` of a reusable workflow: the result is "workflow was not found" and a
  `startup_failure`. git and the REST API do follow it.
* The "invalid lockfile pin" root cause: GitHub checks the called workflow's repository lock at
  the pinned commit and rejects records whose ref is a bare SHA. Fixed by #1314 (case folding in
  `relock-standards-pin.sh`) and `januskey#159`, both merged.
* `GITHUB_TOKEN` cannot push files under `.github/workflows/`, and a human push needs the
  `workflow` OAuth scope. Regenerate a lock with `gh actions-lock` plus the repair chain
  (`relock-sha-keys`, `complete-job-refs`, `close-lock`, `prune-stale`), then verify with
  `update-actions-lock.sh --verify-local`, `check-lock-sync.sh` and
  `check-actions-lock-gate.sh`.
* Do not merge a re-point pull request without its regenerated lock; `hypatia#958` merged first
  and left that repository's callers without the matching lock records.
* `close-lock` learned two sources for a moved tag (#1323, merged): the prior lock record and
  the call-site tag comment. A third, the callee's own lock, landed in #1350.
* #1317 and #1319 (merged) fixed the zero-job Mirror and Self CI failures: the mirror and
  ci-pipeline callers were pinned to a commit that existed only on a deleted branch. Other
  estate repositories pinned there have not been checked.
* About 368 estate callers need the re-point and a lock regeneration (the session's count);
  `gitbot-fleet`'s `fix-stale-reusable-pin.sh` and `stale-reusable-pins.tsv` are keyed on the
  old repository name.
* The UUID v7 to v8 rename: stage 1 is merged (#1260); stages 2 and 3 are the owner's, because
  they change branch protection estate-wide.

== Tooling facts for agents in managed sessions

* `gh` cannot fetch job logs (403); use the MCP `get_job_logs`. GraphQL is blocked; use REST.
* A session proxy allows reads on repositories attached with `add_repo` but blocks `/orgs/*`,
  GraphQL, Pages, `raw.githubusercontent.com` and ruleset PUTs. `add_repo` cannot attach
  repositories whose names begin with a dot, and it lowercases names in its output. The
  `list_repos` `after_id` paging is broken; use per-letter `query` slices.
* Avoid the deprecated names that `scripts/check-canonical-names.sh` rejects. Render AsciiDoc
  with `asciidoctor --failure-level WARN` before committing. The commit hook needs gitleaks and
  mikefarah's Go `yq`: install checksum-verified binaries, do not bypass the hook.
* `kyq` does not build yet ("AffineScript 0.1.1 does not parse src/"), and `kyX` is not a usable
  YAML parser today. Do not claim either as a working gate.
