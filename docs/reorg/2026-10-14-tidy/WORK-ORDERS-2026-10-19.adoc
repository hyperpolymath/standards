== WO-2: mirror honesty (P1.5; #950, #1002)

*Goal.* The Mirror to Git Forges run on `main` is green or honestly
skipped, and the reusable can no longer hide a failure.

*Authority.* Plan row P1.5; D261 for the destinations; applied-unless-struck (D113).

*Facts measured.* Run 39242703018 on `75bd5994`: all seven forge jobs ran,
so all seven `*_MIRROR_ENABLED` repository variables are `true`. GitLab
and Radicle succeeded. Sourcehut, Disroot and Gitea failed at their
"Verify <forge> SSH host" step. Codeberg and Bitbucket passed the host
check and failed at the push step. The reusable is
`.github/workflows/mirror-reusable.yml` (445 lines). The GitLab job
(lines 78 to 140) is the pattern the others copy, and it carries two
failure suppressions: `continue-on-error: true` on the job (line 80) and
on its push step (line 126), so a GitLab failure shows green with a
warning. Line 441 is `rad sync --announce || echo "Radicle sync
attempted"`, which turns a failed sync into a green step. The caller in
this repository is `.github/workflows/mirror.yml`, pinned to the
reusable at `427eb35c`.

*Steps.*
. Read the failing steps' logs for the five red jobs and record the
  reason per forge in the PR body (fingerprint variable absent, host key
  mismatch, destination repository missing, key refused).
. Remove the `|| echo` on line 441. A failed Radicle sync fails the step.
. Remove both GitLab `continue-on-error: true` lines (80 and 126). The
  comment above line 126 explains that GitLab branch protection may block
  the force-push; that is a real failure and must show red, with the
  owner action the comment already names. GitLab passes today, so this
  does not redden `main` by itself.
. Add a destination probe to each forge job, before its push step,
  guarded by the same key-presence check: run `git ls-remote "$REMOTE_URL"`
  with no ref argument and capture its stderr. Exit 0 means reachable,
  including an empty repository awaiting its first push (do not add
  `--exit-code`, which fails on an empty repository), so the push
  proceeds. The probe skips the push, with a `::notice::` naming the
  forge and D261, in exactly one case: a non-zero exit accompanied by
  forge-specific evidence that the repository is absent. Record that
  evidence and its source in the PR body; for example, an authenticated
  forge API check with access sufficient to distinguish an absent
  repository from a private one. Generic stderr such as `not found`,
  `does not exist` or GitLab's `could not be found` is insufficient:
  GitLab can use the same wording for a missing repository and denied
  access. An API 404 alone is likewise insufficient if the forge masks
  denied access that way. If the probe cannot distinguish absence from
  denied access, print the captured stderr and fail the job red. Every
  other non-zero exit, including a refused or revoked key, a host-key
  problem, a transport failure or a DNS miss, also prints the captured
  stderr and fails the job red. `git ls-remote` returns the same status
  (128) for all of these; neither that status nor ambiguous wording
  proves absence, and the default without conclusive evidence is red. A
  reachable destination that refuses the push stays red.
. Add an empty-host guard: when the resolved mirror organisation or host
  is empty, skip with a `::notice::`, never push to an empty path.
. Keep the SSH fingerprint verification exactly as strict as it is.
. Do not edit `actions.lock` unless a `uses:` line changed; if one did,
  regenerate with the repository's own relock tooling, never by hand.
. In the PR body, list the five variables the owner flips to `false` on
  this repository until D261 provisions the forges:
  `SOURCEHUT_MIRROR_ENABLED`, `DISROOT_MIRROR_ENABLED`,
  `GITEA_MIRROR_ENABLED`, `CODEBERG_MIRROR_ENABLED`,
  `BITBUCKET_MIRROR_ENABLED`. Variables are not in the tree; the executor
  cannot set them.

*Acceptance.*
----
test "$(grep -c '|| *echo' .github/workflows/mirror-reusable.yml)" -eq 0            -> no matches (exit 0)
test "$(grep -c 'continue-on-error' .github/workflows/mirror-reusable.yml)" -eq 0   -> no matches (exit 0)
bash scripts/check-workflow-duplicate-keys.sh                       -> clean
bash scripts/lock-selfcheck.sh "$(git rev-parse HEAD)"               -> SELF-CONSISTENT (after push)
Mirror to Git Forges on main after merge: GitLab and Radicle green; every
other forge skipped with a notice (once the variables are flipped) or red
with a named reason, never green on a failure.
----
