== Why this exists

228 open issues. That is the backlog of a standards *estate*, filed one issue per finding,
so the queue mixes four different kinds of object: a two-line script fix, a 400-repository
rollout, a question only the owner can answer, and a tracker that exists to hold other
trackers. Treating them as one queue is why the number feels overwhelming — nothing on the
list tells you which is which. This document sorts every open issue into one of seven tiers,
states the current evidence for the tier, and names what would close it.

Every issue is classified. Nothing here changes GitHub; the companion script
(`scripts/triage-2026-10-24-apply.sh`) is dry-run by default and is how the close list gets
applied without hand-clicking 18 issues.

== The seven tiers

[cols="1,2,7",options="header"]
|===
|Tier |Name |What it means
|C |Close now |Noise, duplicate, superseded, or verified already fixed on main. Each row names the evidence.
|Q |Quick fix |Repo-local, one file or one config/message edit, acceptance already stated in the issue, no ruling needed. Target: under two hours including a test.
|S |Small task |One repository, a real change (script + test, template, spec section, or a bounded sweep of one file set). Half a day to a day.
|E |Estate campaign |Mechanical or near-mechanical, but it lands in other repositories, org rulesets, or needs admin/owner tokens. Value is high; cost is tokens and coordination, not judgement.
|D |Decision required |Blocked on an owner ruling. No amount of coding closes these; each needs a yes/no on a stated question.
|R |Research |The outcome is knowledge or a design, not a patch. Nobody knows the fix yet.
|U |Umbrella / parked |Parent, epic, standing, or parked. These are not work units: they should hold children, not sit in the queue.
|===

The number that matters: *122 of 228* (tiers Q and S) are ordinary work that is
already specified — nothing on those two lists is waiting on a person. A further *14* are already
answered and can be closed today. That is *136 of 228 (60%)* that a single person
with the repository checked out can reduce without asking anybody anything.

The rest is not backlog in the same sense. *68* (E+U) are 47 campaigns and 21 parents —
they are programmes, not tickets, and they should be tracked one level up. *18* are
decisions and *6* are research: neither shrinks by coding.

== Method and evidence

* Read all 228 open issues through the API (title, body, labels, age, comment count), not just titles.
* Re-checked every "red on main" claim against the actual runs of 2026-10-24, because several were filed weeks ago and have since been fixed silently. That check moved 7 issues to tier C on evidence, not opinion.
* Spot-verified the cheap fixes against this checkout: `check-rsr-profile.sh` still never reads `[baseline]` (#1227); `root-allow.txt` is still absent while the exemption ratchet still lists it (#908); `check-uuid-v7.sh` still only inspects the last UUID on a line (#1079); `check-actions-lock-gate.sh` still exempts `actions/github-script` unconditionally (#907); 10 live `*.k9.ncl` files still lack the line-1 sentinel (#1000); 0 of the last 200 commit messages carry a `Debt-exception` trailer (#958); `os_detect.ncl`, `template-capability-gates.toml` and the sweep-classifier defaults still carry the defects their issues describe.
* Did *not* re-verify the estate-number claims (repository counts, per-repo populations). Those are quoted from the issues and tagged as such in the notes; a campaign re-measures before it acts.

Latest default-branch state at the time of writing: `Governance`, `Mirror to Git Forges` and
`AUTO: Propagate Hook Updates` are red; every other main-branch workflow is green. The
Governance red is a single Hypatia baseline finding (down from the 12 in #1173).

== The sequence that actually shrinks the number

The backlog does not come down by working through it in number order. It comes down in this
order, and the first two steps are one focused day each.

. *Close tier C (14 issues, ~1 hour).* `bash scripts/triage-2026-10-24-apply.sh` (dry-run), then `--apply`.
. *Clear tier Q in three passes (61 issues, ~1 day).* The passes are ordered in the table below: gates first, then files that do not evaluate, then noise and seed templates.
. *Answer the decisions (18 rulings).* Most are one sentence each. This unblocks roughly 40 issues in tiers Q/S/E that are waiting on a yes or a no.
. *Convert tier U into children.* Each umbrella gets its open children linked and is then left alone; the parked campaign (#443) closes outright.
. *Only then run tier E,* one campaign at a time, each with its own issue and its own acceptance criteria.
