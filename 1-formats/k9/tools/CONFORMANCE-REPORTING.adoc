= DEED–K9 evidence and compact reporting

`conformance-report.mjs` calls the existing validators, retains their logs and
produces a structured result plus one compact Markdown report. This is local
reporting policy, not a new normative contract. It adds no K9 conformance rules.

== What each category establishes

[cols="1,3,3",options="header"]
|===
|Category |Evidence |Limit
|DEED syntax |The current Bun linter accepts each tracked live deed; a root repo deed exists. |No assertion that metadata is true, complete or authorised.
|Contract typecheck |Pinned Nickel typechecks the normative contract. |Does not establish that every predicate or validator path is correct.
|Validator self-test |Mirror, extractor, capability and attribution assertions execute. |Finite implementation tests, not a proof of validator completeness.
|Positive/negative controls |Valid examples pass; invalid examples fail by their named rule and layer. |Expected rejection is a successful test. Coverage is finite.
|Live corpus L0–L2 |Tracked contracts are checked by the canonical hook with Nickel; changed debt entries lose their exemptions. |Coordination dialects are routed out of scope. L3 signature verification is outside this report.
|===

== Verdicts and counts

* Red: at least one blocking conformance failure is known.
* Orange: required evidence is incomplete, unavailable, interrupted or malformed.
* Yellow: checks completed with permitted advisory debt or warnings.
* Green: all applicable checks in the declared scope completed successfully.
* Grey: explicitly not applicable, with a reason; never a synonym for not run.

Red takes precedence over orange, so missing evidence cannot conceal a known
failure. Indeterminate counts remain visible. Counts are result assertions or
files, not lines of log output. Failed counts include advisory failures, labelled
as such; advisory warnings on a passing file can also produce yellow. A routed
coordination file is N/A, never a validated K9 contract. The combined badge covers
DEED syntax and K9 L0–L2 only; it is no security certification or L3 claim.

== Comparison and evidence

The previous report is read from the latest bot-owned marked PR comment. A
small baseline is embedded in that comment. Compare different revisions of the
same PR only when schema, validator/profile hashes, tool versions, fixture definitions and corpus identities
match and the category has no indeterminate evidence. Arrows mean fewer/more
failed results; equal failures and advisories mean unchanged. Changes to scope or validators
produce `no comparable baseline`, rather than an apparent improvement.

Evidence lives in `tests/conformance/YYYY-MM-DD/pr-N/run-ID-ATTEMPT/` and is
uploaded as a dated CI artifact. The current PR comment is updated in place.
Failures and scope exclusions are expandable; at most 20 details per category
are shown, with full evidence in the artifact. Run and commit identity accompany
the badge. Reports are evidence, not an authority to weaken a gate.

== Reproduce

[source,bash]
----
# Install the workflow's pinned, SHA-256-verified Nickel, and use Bun.
bun test 1-formats/k9/tools/conformance-report.test.mjs
bun 1-formats/k9/tools/conformance-report.mjs
----

Exit 0 means green, yellow or explicit N/A; exit 1 means a blocking failure;
exit 2 means evidence could not establish the verdict. CI retains its required
job name. Existing structural/Mustfile checks still run and can fail the job
independently of this scoped conformance report. No fabricated check status is
posted. Fork PRs use `pull_request`, never privileged `pull_request_target`;
if GitHub denies comment writes, the artifact and job summary remain available.

== Audit changes

The previous self-test workflow used a brace group ending in `echo`, so its
pipeline status could hide the validator's failure. Collection now captures the
actual subprocess exit. The corpus hook previously discarded that exit and
could pass an empty result stream; it now checks both status and result count.
Routed files no longer inflate the conformance count. A separate changed-file
list applies debt policy to the full corpus without narrowing the scan.

The structured reader additionally rejects missing, duplicate, unexpected or
malformed per-file results. Missing tools and unresolvable PR ranges are orange.
Report text escapes input from file paths and diagnostic messages.

The lock membership helper also completes direct workflow refs from existing
resolved dependencies. Its regression verifies idempotence; offline
`gh-actions-lock --verify-local` checks that no new unresolved pin was invented.
The full authenticated relock is unavailable in this environment; no dependency
digest was changed.
