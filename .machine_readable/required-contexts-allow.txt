# required-contexts-allow.txt — SHRINK-ONLY list of required contexts that are
# known to be unsatisfiable on a pull request.
#
# Every line is a debt with a name and a reason: `context`
#
# THE LIST IS EMPTY, AND THAT IS THE POINT
# ----------------------------------------
# This file's preamble has always said that removing the last entry is the
# goal and not an edge case. The one entry has now been removed, because the
# defect it recorded was repaired at the decision layer rather than declared
# here. Empty is the correct resting state; if an entry comes back, it is a
# regression with a review trail, not a configuration.
#
# WHY THIS FILE EXISTS INSTEAD OF `continue-on-error: true`
# ---------------------------------------------------------
# The alternative was an always-green advisory job, and this repository has
# already paid for that: a gate that reports the same colour on every pull
# request is indistinguishable from a gate that is satisfied. (It is also how
# `scripts/check-required-contexts.sh` itself went unnoticed for a month — it
# was never wired, so it never disagreed with anything.)
#
# So the job FAILS on any unsatisfiable required context that is not listed
# here. A new entry cannot be added quietly: this file is the review surface,
# and the gate also warns when a listed context stops appearing as a finding, so
# this file cannot quietly rot into a museum of old exemptions either.
#
# RECORD OF THE RETIRED ENTRY
# ---------------------------
# Context: `scan / Hypatia Neurosymbolic Analysis`
# Retired: 2026-10-24
#
# It named the second call site of hypatia-scan-reusable.yml. `hypatia-scan.yml`
# declares that job as push/schedule-only on purpose, so the same findings are
# not uploaded to code scanning twice per pull request; the pull-request call
# site is the fork-governance lane, which publishes
# `Hypatia verdict grid / Hypatia Neurosymbolic Analysis`. A required check is
# matched by name, and the names differ, so the required one could never be
# produced while a pull request was open.
#
# Measured consequence: #1336 reached 65 passing checks, a cleared
# reviewDecision and mergeable=MERGEABLE while mergeStateStatus stayed BLOCKED.
# #1337, which carried the repair, merged 79 minutes BEFORE the ruleset was
# corrected — so the fix provably did not enable its own merge. #1337's merge
# used the ruleset's `always` bypass, which discards every required check in the
# same action. This record does not establish that #1336 merged or used the bypass.
#
# Retired by the decision layer, as this file asked:
#   ruleset 23787415, required_status_checks:
#     scan / Hypatia Neurosymbolic Analysis
#       -> Hypatia verdict grid / Hypatia Neurosymbolic Analysis
#   bypass_actors: always on RepositoryRole:5 -> removed
#   strict_required_status_checks_policy: false -> true
#   + `Repo self-tests` required (21 contexts, all producible on a pull request)
#
# Doing it in this file instead would have required continuing to bypass, and a
# list of declared exceptions is only safer than a bypass while it stays short.
#
# Format: one context per line; `#` starts a comment; blank lines ignored.
#
# An empty file (or one holding only comments) asserts that no repository-owned
# `PR-UNPRODUCIBLE` or `UNSATISFIABLE` finding is undeclared. It does
# NOT assert that every required context is satisfiable: the reconciliation step
# excludes `app-owned` contexts (those produced by a GitHub App other than
# Actions), and it only judges contexts that are findings. Both exclusions are
# deliberate — but they mean empty is a narrower claim than "all good", and
# this file should not be read as one.
