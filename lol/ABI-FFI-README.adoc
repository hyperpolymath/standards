== LOL i18n Service — ABI/FFI/API Triple Documentation

=== Overview

The LOL (Language of Languages) i18n service follows the *Hyperpolymath
ABI/FFI/API Triple Standard*:

* *ABI (Application Binary Interface)* defined in *Idris2* with formal
proofs
* *FFI (Foreign Function Interface)* implemented in *Zig* for C
compatibility
* *API* exposed via a *Zig* gateway (REST/gRPC/GraphQL) for idiomatic
high-level access

LOL is always called as a service, never embedded. Consumers initialise
with `+lol_init()+`, perform translation lookups and plural form
selection across 1500+ languages, then clean up with `+lol_free()+`.

____
*Note:* V-lang was the previous API layer and was banned estate-wide on
2026-04-10. The sidelined V-lang wrappers under `+api/v-lol/+` and
`+api/v-gateway/+` remain only for historical reference. See their
respective `+MIGRATION.adoc+` files for details.
____

=== Formal Proofs (Idris2 ABI)

The Idris2 ABI layer provides the following compile-time guarantees:

[arabic]
. *Result code round-trip*: `+resultFromInt (resultToInt r) = Just r+`
for all `+r+`
. *Plural category round-trip*:
`+pluralFromInt (pluralToInt p) = Just p+` for all `+p+`
. *Result code injectivity*: distinct results map to distinct integer
codes
. *Handle non-null*: the `+Handle+` type cannot wrap a null pointer
(enforced by `+So+`)
. *Struct alignment*: all C struct layouts are proven to have correctly
aligned fields
. *Plural form count bounds*: `+PluralRule.formCount+` is proven to be
in range 1-6
. *BCP-47 validation*: `+ValidLocale+` proves tag structure at
construction (Locale.idr)
. *Translation key validity*: `+ValidKey+` proves non-empty
dot-separated segments (TranslationKey.idr)
. *Plural coverage*: `+eastAsianPluralConstant+` proves East Asian
always returns Other (PluralForm.idr)
. *Plural FFI bounds*: `+pluralToIntBounded+` proves category integers
stay in 0-5 range
. *Store lookup guarantee*: `+CorrectStore+` interface proves key-exists
implies non-empty result (I18nStore.idr)
. *Fallback chain contract*: `+lookupWithFallback+` walks chain with
locale/key pair, resolves or returns Nothing

No `+believe_me+`, `+assert_total+`, or other escape hatches are used.

=== Building

==== Idris2 ABI

[source,bash]
----
idris2 --check lol-abi.ipkg   # Type-check all ABI definitions and proofs
idris2 --build lol-abi.ipkg   # Build (optional, ABI is specification-only)
----

==== Zig FFI

[source,bash]
----
cd ffi/zig
zig build              # Builds liblol.so and liblol.a
zig build test         # Runs unit tests
zig build test-integration  # Runs integration tests
----

==== Zig API Gateway

[source,bash]
----
cd api/zig-gateway
zig build
./zig-out/bin/lol-gateway
----

Default base port is 7800. Configure via `+LOL_PORT+` environment
variable. Corpus data directory defaults to `+corpus+`; set via
`+LOL_DATA_DIR+`.

=== Usage (Zig gateway, HTTP)

The Zig API gateway exposes three endpoint families:

*REST API* (HTTP on port 7800):

[source,bash]
----
curl http://localhost:7800/api/v1/languages
curl http://localhost:7800/api/v1/corpus/stats
----

*gRPC JSON-compatible* (on port 7801):

[source,bash]
----
curl -X POST http://localhost:7801/lol.TranslationService/Translate \
  -H "Content-Type: application/json" \
  -d '{"locale":"en-US","key":"app.greeting"}'
----

*GraphQL* (on port 7802, endpoint `+/graphql+`):

[source,bash]
----
curl -X POST http://localhost:7802/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"{ languages { code name } }"}'
----
