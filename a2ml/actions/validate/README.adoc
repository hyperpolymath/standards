= Validate A2ML Manifests -- GitHub Action
:author: Jonathan D.A. Jewell
:toc: preamble
:icons: font

== Overview

GitHub Action that scans a repository for `.a2ml` files and validates their structure,
required fields, and compliance with the
https://github.com/hyperpolymath/standards/tree/main/a2ml[A2ML specification].

A2ML (Attested Markup Language) is the manifest format used across
https://github.com/hyperpolymath/standards[RSR (Rhodium Standard Repository)] projects to
declare machine-readable metadata, AI agent instructions, attestation provenance, and
project state.

== What It Validates

[cols="1,3"]
|===
| Check | Description

| SPDX header
| Verifies `SPDX-License-Identifier` is present in the first 10 lines of each file.

| Identity fields
| Requires at least one of `agent-id`, `name`, or `project` at the top level. Relaxed for
  files matching `*AI-MANIFEST*` which use free-form markdown-style headers.

| Version field
| Checks for `version` or `schema_version` (warning if missing).

| Attestation blocks
| If an `[attestation]` or `## Attestation` section exists, validates it contains at least
  one of `proof`, `signature`, `hash`, or `verified` fields.

| Section syntax
| Warns on `[section]` headings with unclosed brackets (catches malformed sections).
|===

== Usage

Add this step to any GitHub Actions workflow:

[source,yaml]
----
name: Validate A2ML
on: [push, pull_request]

permissions:
  contents: read

jobs:
  validate-a2ml:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hyperpolymath/standards/a2ml/actions/validate@main
        with:
          path: '.'        # Directory to scan (default: repo root)
          strict: 'false'  # Promote warnings to errors (default: false)
----

=== Inputs

[cols="1,1,3"]
|===
| Input | Default | Description

| `path`
| `.`
| Directory path to scan for `.a2ml` files. The scan is recursive, excluding `.git/`.

| `strict`
| `false`
| When `true`, all warnings are promoted to errors and the action fails on any validation
  issue. Recommended for repositories that require full A2ML compliance.
|===

=== Outputs

[cols="1,3"]
|===
| Output | Description

| `files-scanned`
| Number of `.a2ml` files discovered and processed.

| `errors`
| Count of validation errors. The action exits with code 1 if this is non-zero.

| `warnings`
| Count of validation warnings. In strict mode, these are counted as errors instead.
|===

== Exit Codes

[cols="1,3"]
|===
| Code | Meaning

| `0`
| All files valid (or only warnings in non-strict mode). Also returned when no `.a2ml`
  files are found (with a `::notice::` annotation).

| `1`
| One or more validation errors were found. In strict mode, this includes promoted warnings.
|===

== Strict Mode

In strict mode (`strict: 'true'`), all warnings are promoted to errors:

* Missing SPDX header becomes a blocking error
* Missing version field becomes a blocking error
* Empty attestation blocks become a blocking error

This is the recommended setting for repositories following the RSR standard.

== GitHub Annotations

The action produces GitHub annotations (errors, warnings, notices) that appear inline in
pull request diffs and the Actions summary. Each annotation includes the file path, line
number, and a description of the issue.
