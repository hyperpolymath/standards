= A2ML Pandoc Reader & Writer
:author: Jonathan D.A. Jewell
:revdate: 2026-03-01

== Overview

`a2ml.lua` is a https://pandoc.org/custom-readers.html[Pandoc custom reader]
that converts A2ML (Attested Markup Language) surface syntax into the Pandoc
AST. This enables converting A2ML documents to any format Pandoc supports:
HTML, Markdown, LaTeX, PDF, DOCX, EPUB, and dozens more.

== Usage

[source,sh]
----
# A2ML → HTML
pandoc -f a2ml.lua input.a2ml -o output.html

# A2ML → Markdown
pandoc -f a2ml.lua input.a2ml -t markdown

# A2ML → PDF (via LaTeX)
pandoc -f a2ml.lua input.a2ml -o output.pdf

# A2ML → DOCX
pandoc -f a2ml.lua input.a2ml -o output.docx

# A2ML → JSON AST (for programmatic use)
pandoc -f a2ml.lua input.a2ml -t json
----

== Supported A2ML Features

[cols="1,3"]
|===
| Feature | Pandoc Mapping

| `# Heading` through `##### Heading`
| `Header` (levels 1-5) with auto-generated IDs

| `@directive(attrs): ... @end`
| `Div` with `data-a2ml` attribute and CSS classes

| `@opaque(lang="x"): ... @end`
| `CodeBlock` preserving bytes exactly

| `**bold**`
| `Strong`

| `*italic*`
| `Emph`

| `[label](url)`
| `Link`

| `@ref(id)`
| `Link` targeting `#id` (internal cross-reference)

| `- list items`
| `BulletList`

| `\`\`\`lang ... \`\`\``
| `CodeBlock` with language annotation

| Paragraphs (blank-line separated)
| `Para`
|===

== Directive Handling

A2ML directives are rendered as Pandoc `Div` elements with:

- `id` from the directive's `id` attribute (if present)
- CSS class `a2ml-<name>` (e.g. `a2ml-abstract`, `a2ml-fig`)
- `data-a2ml` HTML attribute matching the directive name
- Additional attributes as `data-*` pairs

The `@opaque` directive is special: its body is rendered as a `CodeBlock`
to preserve byte-exact content, matching the A2ML spec requirement for
deterministic round-tripping.

== Requirements

- Pandoc 3.0+ with Lua support (`+lua` feature)

== Writer Usage

`a2ml-writer.lua` converts any Pandoc-supported format to A2ML:

[source,sh]
----
# Markdown → A2ML
pandoc input.md -t a2ml-writer.lua -o output.a2ml

# HTML → A2ML
pandoc input.html -t a2ml-writer.lua -o output.a2ml

# Round-trip: A2ML → AST → A2ML
pandoc -f a2ml.lua input.a2ml -t a2ml-writer.lua -o roundtrip.a2ml
----

The writer produces:

- `#` headings from `Header` elements
- `@directive: ... @end` from `Div` elements with `a2ml-*` classes
- `@abstract: ... @end` from `BlockQuote` elements
- Fenced code blocks with language annotations
- `@ref()` for internal cross-references
- SPDX header on all output

== Filter: a2ml-filter.lua

`a2ml-filter.lua` is a Pandoc Lua filter that provides post-processing
passes over the AST produced by the A2ML reader. Run it with `--lua-filter`:

[source,sh]
----
# Full pipeline: read + filter + template
pandoc -f a2ml.lua input.a2ml \
  --lua-filter=a2ml-filter.lua \
  --template=a2ml.html \
  -o output.html
----

=== Capabilities

[cols="1,3"]
|===
| Feature | Description

| Cross-reference resolver
| `@ref(id)` links are validated against actual heading anchors. Resolved refs
  get a tooltip; unresolved refs produce a warning and red styling.

| Include directive
| `@include(file.a2ml)` Div elements are replaced with the parsed content of
  the referenced file via `pandoc.read()`. Missing files produce a visible
  error block rather than silent failure.

| TOC generator
| Auto-generates a Table of Contents from all document headings. Inserted
  after the first level-1 heading (or at the top if none exists).

| Diagram rendering
| Code blocks tagged `mermaid` or `graphviz`/`dot` are rendered to inline SVG
  via `pandoc.pipe()`. Falls back gracefully to showing source code if the
  external tool (mmdc, dot) is not installed.

| SPDX validator
| Checks for `SPDX-License-Identifier` in metadata or early document blocks.
  Warns if missing (can be disabled via `a2ml-validate: false` in metadata).

| Metadata enrichment
| Populates `version`, `date`, and `author` from git (`git describe`,
  `git log`, `git config`) when not already present in the document.
|===

=== Disabling Capabilities

Set metadata flags to disable individual features:

[source,yaml]
----
---
a2ml-includes: false
a2ml-diagrams: false
a2ml-validate: false
---
----

== HTML Template: a2ml.html

`a2ml.html` is a Pandoc HTML5 template purpose-built for A2ML documents:

[source,sh]
----
pandoc -f a2ml.lua input.a2ml \
  --lua-filter=a2ml-filter.lua \
  --template=a2ml.html \
  -o output.html
----

=== Template Features

- **SPDX badge** in the document header showing the license identifier
- **Directive styling**: `@abstract` (blue), `@opaque` (amber), `@fig` (green),
  `@note` (orange), `@warning` (red) — each with distinct borders, backgrounds,
  and auto-generated labels
- **Responsive layout**: fluid max-width container, mobile breakpoints
- **Print-friendly**: clean monochrome output, URLs expanded inline
- **Syntax highlighting**: full Pandoc highlight token coverage
- **TOC styling**: collapsible grey box for the generated table of contents
- **Diagram blocks**: centred SVG container with fallback source display
- **Cross-reference colouring**: resolved refs in blue, unresolved in red

=== Template Variables

The template consumes these Pandoc metadata fields:

- `$title$` — document title
- `$author$` — author name
- `$date$` — document date
- `$version$` — document version
- `$spdx-license$` — SPDX license identifier
- `$a2ml-format$` — A2ML format version

== Extensions Table

Both the reader and filter advertise an extensions table:

|===

| `+validate`
| Structural validation (SPDX, cross-references)
|===

== Spec Compliance

This reader implements the A2ML v1.0.0 surface syntax as specified in
`SPEC-v1.0.adoc`. Test vectors in `tests/vectors/` validate correct
output for all core constructs.
